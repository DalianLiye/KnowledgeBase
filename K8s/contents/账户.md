# 关于K8s账户
K8s集群有以下两类用户：
- 服务账户(Service Account)
- 普通账户(UserAccount)


# 普通账户(UserAccount)
普通账户面向外部人员或独立服务，例如登录Dashboard所用账号\
该账户由集群管理员分发密钥，账号信息通常存储在用户名、密码清单类文件中

**注：**\
K8s不支持通过API接口创建普通账户


# 服务账户(Service Account)
Pod运行时需要通过服务账户来访问Kubernetes API

服务账户由K8s自身管理，依托三类控制器实现自动化运维：

- **Service Account Admission Controller**\
  Admission Controller属于kube-apiserver组件，负责在Pod创建或更新时，会同步对Pod进行修改，自动为Pod注入与服务账号相关的配置，确保Pod能正确使用K8s的身份认证和镜像拉取凭证
  
  当Admission Controller插件处于激活状态下（在大多数发行版中都默认情况）创建或修改Pod时，会按以下操作执行：
  
  1) 如果创建Pod时没有设置服务账号，Service Account Controller为每个命名空间创建默认的服务账号

  2) 如果Pod引用的服务账号不存在，将会拒绝请求，最终导致Pod创建失败

  3) 如果Pod不包含任何imagePullSecrets, 则将服务账号的imagePullSecrets会添加到Pod中(前提是Service Account要有配置imagePullSecrets)，好处就是无需为每个Pod执行imagePullSecrets，只要跟服务账号绑定即可

  4) 为包含API访问的Token的Pod添加了一个volume\
     当Pod需要访问K8s API时，是需要身份认证的，这通常通过挂载一个包含访问Token的Secret来实现\
     Admission Controller会为Pod自动挂载一个包含服务账号Token的Secret，这样Pod内部的应用就可以通过该Token访问API了\
     Admission Controller会自动创建一个名为kubernetes.io/service-account-token类型的Secret，并将该Secret以Volume的形式挂载到Pod中

  5) 把volumeSource添加到Pod的每个容器中\
     挂载路径：/var/run/secrets/kubernetes.io/serviceaccount

 - **Token Controller**\
   Token Controller主要管理和维护与服务账户Token相关的Secret对象，包括：
   - 创建服务账户时，自动创建服务账户Token Secret
   - 监控服务账户变化，并自动刷新和更新Token
   - 删除服务账户时，清理过期或无用的Token Secret
    
- **Service Account Controller**\
  Service Account Controller主要用来管理命名空间下的服务账户，它会确保每个有效的命名空间中都存在一个名为"default"的服务账户\
  默认情况下，如果用户没有显式指定Pod使用哪个服务账户，系统会自动使用default账号，从而避免Pod没有服务账户导致无法访问API或认证失败

服务账号相关命令：
```shell
kubectl get sa -n <namepsace>
kubectl get serviceaccount -n <namepsace>
```


# 服务账户和普通账户的比较
- **使用对象**\
  - 普通账户：面向人员用户
  - 服务账户：面向Pod内运行的进程
- **作用范围**\
  - 普通账户：集群全局，名称在整个集群唯一
  - 服务账户：隶属于指定命名空间
- **创建与管理**\
  - 普通账户：创建需特殊权限，常对接企业用户体系
  - 服务账户：轻量化，集群用户可按需为特定任务创建
- **其他**\
  - 两类账户的审计要求不同
  - 复杂系统配置中，一般会配套定义各组件的服务账户
