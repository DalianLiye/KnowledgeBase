# 关于RDD
全称：Resilient Distributed Dataset，弹性分布式数据集

大体上来说，每一个Spark应用程序都包含一个驱动程序（driver program）
驱动程序运行用户的main主函数，并在集群上执行各类并行运算

RDD是一组具备容错能力的元素集合，数据被分片分布在集群各个节点上，可以对其执行并行运算
元素可以是任意类型的元素
RDD本身不携带真实业务数据，它只保存元数据，比如：
- 分区信息
- 依赖关系
- 计算逻辑
- 分片策略

真正的数据初始保存在原始数据源，不在Executor
触发Action计算之后，真实数据才会加载到Executor节点的内存/磁盘

RDD是逻辑上的分布式元素集合，模型上数据被分片分布在集群各个节点，支持并行处理
刚定义RDD对象时，只是构建计算逻辑，真实数据还没有分发到集群
只有触发Action行动算子之后，才会触发Job，真实数据才会被读取、物理分布到集群各个Executor节点执行计算

RDD是不可变，一旦创建不能修改，转换操作会生成新RDD，保存血缘依赖

# RDD持久化
Spark可以把RDD持久化（persist）到内存，在多次并行计算之间高效复用该数据集
并且RDD可以自动处理节点故障，实现容错恢复
如果不进行持久化，每一次Action都会重新根据血缘重新计算RDD


# RDD对象和RDD元素
RDD对象和RDD元素不是同一个概念
- **RDD对象**
  只存元数据（分区、血缘、逻辑），不持有真实业务数据实例
- **RDD元素**
  指将来执行任务后，Executor上会生成的那一条条业务对象/记录

比如一个Java的List类对象，里面包含元素是User类对象，比如：
```java
List list01 = new List[User]
```
那么，RDD对象就是list01，RDD元素就是list01中的各个User类对象


## RDD元素
RDD元素就是一条条业务数据记录，可以是任意JVM类型（数字、字符串、元组、自定义对象）
- Driver上的RDD对象保存了分片策略、血缘依赖、数据读取逻辑等元数据（计算蓝图）
- RDD对象不存储真实的元素数据，真实元素存放在原始数据源(HDFS磁盘/Driver本地List)，Action执行后出现在Executor内存/磁盘
