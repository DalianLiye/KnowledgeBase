# 关于配置热更新
配置热更新（Hot Configuration Reload）就是不重启应用/容器，就能把新配置加载到运行中的进程里并生效\
传统方式：改配置 → 重启服务 → 新配置生效（有downtime）\
热更新：改配置 → 不重启 → 几秒内新配置生效（无downtime）


# ConfigMap&Secret和配置热更新
修改ConfigMap和Secret配置后，能否同步至Pod容器内需要考虑它们的使用方式：

- **环境变量注入**\
  配置更新不会同步\
  从ConfigMap/Secret注入的环境变量在Pod启动时固化，后续修改资源配置无法自动更新环境变量，需重建Pod生效

- **单文件挂载(subPath)**\
  配置更新不会同步\
  subPath单独挂载的文件在Pod启动后直接一次性复制到容器，后续ConfigMap/Secret如何更新都与该文件无关

  替代方案：\
  将ConfigMap/Secret挂载至容器独立空目录（如/temp/nginx/），原目录/etc/nginx不受挂载覆盖\
  再在/etc/nginx中创建软链接指向挂载目录里的配置文件

  若目标路径原有配置文件阻碍软链接创建，可通过初始化容器提前删除原文件（不推荐PostStart，易与容器启动命令冲突）\
  示例：nginx.conf挂载到/temp/nginx/nginx.conf，在/etc/nginx/建立软链接指向该文件，依托目录挂载实现配置自动更新

- **Volume整目录挂载**\
  配置变更可同步\
  Volume整目录挂载实际上是挂载一个 “会自动换底层目录”的特殊目录，目录里的文件全是软链接\
  kubelet周期性（默认约 60s）同步缓存，变更延迟取决于同步间隔
