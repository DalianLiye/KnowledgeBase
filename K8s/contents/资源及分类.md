# 关于资源
K8s理念：一切皆资源，万物皆对象\
如果将K8s资源比作Java类，K8s对象是基于资源定义创建的实例

K8s中的所有内容都被抽象为"资源"\
资源类别包括：Pod，Service，Node等\
K8s对象就是资源的实例，是持久化的实体，例如：某个具体的pod或Node

K8s通过这些实体描绘出整个集群的状态\
集群里每一个真实组件，都会对应一个K8s对象实例，比如哪些个节点，Pod，Service对象\
K8s通过这些实例来记录、管控集群当下真实情况

对象的创建，删除，修改都是通过"kubernetes API"，也就是kube-apiserver组件提供的API接口实现的\
命令行工具kubectl实际上也是调用kubernetes API

可以通过"kubectl命令 + 配置文件"来创建这些对象\
配置文件就是声明式定义对象期望状态的文件\
配置文件格式可以是json或yaml，生产环境常用yaml


# 关于资源分类
资源分类方式：
- 按作用域分类
- 按功能分类
- 按API组分类


# 按作用域分类
资源按作用域，主要分为：
- **集群级资源(Cluster)**\
  作用于整个集群，不属于任何命名空间，全集群范围内共享

- **命名空间级资源(Namespaces)**\
  仅作用于当前命名空间，同命名空间内资源可相互访问\
  不同命名空间资源相互隔离、互不干扰\
  K8s命名空间级资源,主要包括：业务、服务、配置、权限、伸缩相关的资源


## 按功能分类
资源按功能类型，主要分为:
- 工作负载类 
- 服务类 
- 配置和存储类 
- 身份认证类  
- 鉴权类  
- 策略类  
- 扩展类  
- 集群类 
- 公共定义类

**注:**\
官方文档(英文版)是按照API组分类的，此分类为官方文档(中文版)的分类方式\
目的是便于入门和理解，但严谨的分类都已英文版为准


## 按API组分类
API组是K8s对API资源的分类组织方式，可理解为资源目录，将功能相近的资源归类管理，便于运维、扩展与版本控制\
早期K8s仅有单个core核心组，资源混杂、扩展性差\
引入API组后，不同功能的资源可独立迭代、单独版本管理，同时也支持扩展第三方自定义资源\
因为API组就是按照功能类型划分的，所以日常按功能对资源划分，本质就是按照API组进行分类

资源按API组，主要分为:
- Core
- Apps
- Storage
- Networking
- Batch
- Rbac
- Autoscaling
