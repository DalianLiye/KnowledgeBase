# 关于控制器
控制器是K8s集群的组件，包含多种类型，负责持续将集群实际状态调整为期望状态\
控制器对K8s各类资源进行管理，资源涵盖Pod、节点、任务、调度等不同层面


# 控制器分类
控制器按职能与使用方,分为两类：
- 系统内置控制器
- 用户可自定义控制器（工作负载控制器）


# 系统内置控制器
属于集群后台组件，运行于kube-controller-manager\
用户无法创建/自定义，仅可观测其管理的资源，负责维护集群基础状态

系统内置控制器主要包括：
- **节点控制器(node controller)**\
  负责节点出现故障时，做出监测、通知与响应处理
- **任务控制器(job controller)**\
  监测一次性任务Job对象，创建Pod运行任务直至执行完成
- **端点分片控制器(endpointslice controller)**\
  维护并填充EndpointSlice对象，建立Service与Pod之间的关联\
  具体作用：
  1) 监听：Service、Pod、Node变化
  2) 自动生成/更新：EndpointSlice（端点分片）
  3) 作用：记录每个Service背后到底有哪些Pod（IP + 端口）,让kube-proxy知道把流量转发到哪些Pod
- **服务账号控制器(servce account controller)**\
  为新建命名空间自动创建默认服务账号


# 用户可自定义控制器
属于标准API资源，支持YAML编排\
由用户创建运维，专门管理业务Pod，承载应用服务\
作用域:命名空间级

按照不同类型的服务，需要搭配对应的用户自定义控制器进行部署

按照服务场景，控制器主要分以下几类：
- 无状态服务控制器: ReplicationController,ReplicaSet,Deployment
- 有状态服务控制器: StatefulSet
- 守护进程服务控制器: DaemonSet
- 任务/定时任务控制器: job,cronjob
 
**注:**\
ReplicationController和ReplicaSet可以直接创建，但一般建议创建Deployment
