## 污点和容忍
通过污点和容忍，可以灵活地让Pod避开某些节点或者将Pod从某些节点驱逐


### 污点(Taint)
污点是标注在节点上的，用来控制哪些Pod可以调度到该节点上\
当在一个节点上打上污点后，k8s会认为尽量不要将Pod调度到该节点上, 除非该Pod表示可以容忍该污点\
一个节点可以打多个污点，Pod只有能容忍所有污点，它才会被调度到该节点

为节点打上污点，执行命令:
```yaml
kubectl taint node k8s-master key=value:NoSchedule
```

为节点移除污点，执行命令:
```yaml
kubectl taint node k8s-master key=value:NoSchedule-
```

查看污点,执行命令:
```yaml
kubectl describe no k8s-master  # 查看具体的配置
```


污点效果：

- **NoSchedule**\
  污点会阻止新的Pod被调度到该节点上，除非 Pod有对应的容忍\
  **具体效果：**
  - 如果新创建的Pod没有容忍该污点，则不会被调度到这个节点
  - 已经运行在该节点上的 Pod 不受影响，仍然继续运行

  **应用场景:**\ 
  节点暂时不适合调度新 Pod，比如节点维护中、资源紧张等

- **NoExecute**\
  污点不仅阻止新的Pod调度到该节点，还会驱逐已经运行在该节点上且没有容忍该污点的Pod

  **具体效果：**
  - 新Pod没有容忍该污点，不能调度到该节点
  - 已经运行的Pod如果没有容忍该污点，会被驱逐（删除），从节点上移除
  - 已经运行的Pod如果能容忍且没有配置tolerationSeconds属性，则可以一直运行
  - 已经运行的Pod如果能容忍且配置了tolerationSeconds属性，比如tolerationSeconds: 3600属性，则该Pod还能继续在该节点运行3600秒

  **应用场景：**\
  节点出现严重故障或不适合继续运行 Pod，需要立即清理节点上的 Pod


### 容忍(Toleration)
容忍是标注在Pod上的，可以灵活地让Pod选择某些节点\
当Pod被调度时，如果没有配置容忍，则该Pod不会被调度到有污点的节点上\
只有该Pod上标注了容忍某些节点的所有污点，则会被调度到这些节点

在Pod的spec下面配置容忍
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx
  labels:
    env: test
spec:
  containers:
  - name: nginx
    image: nginx
    imagePullPolicy: IfNotPresent
  tolerations:
  - key: "example-key"
    operator: "Exists"
    effect: "NoSchedule"
```

```yaml
tolerations:
- key: "污点的key"
  value: "污点的value"
  effect: "NoSchedule" # 污点产生的影响
  operator: "Equal" # 表示value与污点的value要相等，也可以设置为Exists，表示存在key即可，此时可以不用配置value
```
**注：**
1) 如果是将容忍的配置追加在deploy配置中的话，需要在template下加, 因为deploy的template下才是定义Pod的地方
2) Pod容忍一个污点，除了污点的key和value要匹配，effect也要一致


Operator主要包含以下几种：
- **Equal**\
  表示Pod的容忍必须与污点值的key和value相同，才表示该Pod能够容忍该污点

- **Exists**\
  表示Pod的容忍只要与污点的key相同(只比较key，不比较value，不关心value是什么)，即只要key存在就表示该Pod能够容忍该污点
