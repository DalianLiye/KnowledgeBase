# 关于污点和容忍
节点可通过污点（Taint）拒绝普通Pod调度，甚至驱逐已运行的Pod\
Pod配置容忍（Toleration）后，才能匹配对应污点、正常运行在该节点

污点作用在节点，排斥Pod\
容忍作用在Pod，允许自己忽略污点\
节点多污点 → Pod必须全部容忍才能调度


# 污点(Taint)
污点是设置在节点上的调度排斥规则，用于限制Pod调度到当前节点\
当节点配置污点后，默认拒绝无法容忍该污点的Pod调度\
只有Pod配置了对应的容忍（Toleration），才能正常调度到该节点\
一个节点可以配置多个污点，Pod必须容忍节点上所有污点，才允许被调度到该节点

污点策略：
- **NoSchedule**\
  强制策略，污点会强制阻止新的Pod被调度到该节点上，除非Pod配置了对应的容忍
  **具体效果：**
  - 新创建的Pod：没有容忍 → 绝对不会调度到该节点
  - 已运行在该节点上的Pod：完全不受影响，继续正常运行
  **应用场景:**\ 
  节点暂时不适合调度新Pod，比如节点维护中、资源紧张等

- **PreferNoSchedule**\ 
  柔性（尽量）策略，调度器尽量不把Pod调度到该节点，但实在没有其他节点时，仍可调度
  **具体效果：**\
  - 没有容忍的Pod：尽量不调度，但不是绝对禁止
  - 已运行的Pod：不受影响
  **应用场景：**\ 
  希望优先避免调度，但不绝对排斥

- **NoExecute**\
  最强策略, 污点不仅阻止新的Pod调度到该节点，还会驱逐已经运行在该节点上且没有容忍该污点的Pod
  **具体效果：**
  - 新Pod：没有容忍 → 禁止调度
  - 已运行Pod：
    - 没有容忍 → 会被驱逐出节点（删除）
    - 能容忍 + 未配置tolerationSeconds属性 → 可以一直运行
    - 能容忍 + 配置tolerationSeconds属性(比如tolerationSeconds:3600) → 该Pod还能继续在该节点运行3600秒
  **应用场景：**\
  节点出现严重故障或不适合继续运行Pod，需要立即清理节点上的Pod


为节点打上污点，执行命令:
```yaml
kubectl taint node k8s-master key=value:NoSchedule
```

为节点移除污点，执行命令:
```yaml
kubectl taint node k8s-master key=value:NoSchedule-
```

查看污点,执行命令:
```yaml
kubectl describe no k8s-master  # 查看具体的配置
```


# 容忍(Toleration)
容忍是配置在Pod上的规则，用于匹配节点上的污点

当Pod被调度时：
- Pod没有配置容忍，则无法调度到带有污点的节点
- Pod配置容忍 + 容忍不能匹配节点上的所有污点 -> Pod无法被调度到该节点
- Pod配置容忍 + 容忍能匹配节点上的所有污点 -> Pod被调度到该节点


## 示例
在Pod的spec下面配置容忍
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx
  labels:
    env: test
spec:
  containers:
  - name: nginx
    image: nginx
    imagePullPolicy: IfNotPresent
  tolerations:
  - key: "example-key"
    operator: "Exists"
    effect: "NoSchedule"
```

```yaml
tolerations:
- key: "污点的key"
  value: "污点的value"
  effect: "NoSchedule" # 污点产生的影响
  operator: "Equal" # 表示value与污点的value要相等，也可以设置为Exists，表示存在key即可，此时可以不用配置value
```
**注：**
1) 如果是将容忍的配置追加在deploy配置中的话，需要在template下加, 因为deploy的template下才是定义Pod的地方
2) Pod容忍一个污点，除了污点的key和value要匹配，effect也要一致


Operator主要包含以下几种：
- **Equal**\
  表示Pod的容忍必须与污点值的key和value相同，才表示该Pod能够容忍该污点

- **Exists**\
  表示Pod的容忍只要与污点的key相同(只比较key，不比较value，不关心value是什么)，即只要key存在就表示该Pod能够容忍该污点
